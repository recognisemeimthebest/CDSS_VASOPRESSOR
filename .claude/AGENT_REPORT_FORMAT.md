# 에이전트 보고서 표준 포맷

모든 도메인/평가 에이전트는 작업 종료 시 **반드시** 아래 4개 섹션을 포함한 보고서를 출력한다. "끝났습니다" 같은 단답 종료 금지.

---

## 표준 섹션

```markdown
## 발견 (Findings)
- 작업 중 알게 된 사실, 데이터 특성, 제약사항, 예외 케이스
- 가정과 실제가 어긋난 지점
- 코드/데이터에서 미리 정해두지 않았던 발견
- 예: "sepsis3 코호트에 18세 미만 32명 발견 → 필터링함"

## 수정 (Changes)
- 어떤 파일을 어떻게 변경했는지 (경로 + 한 줄 요약)
- 신규 추가/삭제된 파일
- 주요 함수 시그니처 변경
- 예: "src/cohort.py: 신규. sepsis3 + 성인 + first 72h ICU 필터, return DataFrame"

## 판단 근거 (Rationale)
- 왜 이 방식을 선택했는지
- 검토하고 버린 대안 + 폐기 이유
- 임상/통계/공학적 트레이드오프
- 예: "4h binning vs 1h: AI Clinician 표준 + 데이터 희박성 고려해서 4h 채택"

## 미해결 (Open)
- 남은 문제, 다음 세션이 이어 받을 작업
- 결정 보류 사항 (사용자 입력 필요)
- TODO 코멘트 위치
- 예: "결측 처리 정책 미확정 — forward-fill vs 평균 대체 EDA 필요"
```

---

## 작성 규칙

1. **간결하게**: 각 항목 한두 줄. 길어지면 별도 문서로 분리하고 링크.
2. **구체적으로**: 파일 경로, 함수명, 라인번호 포함. "수정함" 같은 모호한 표현 금지.
3. **정직하게**: 부분 완료/실패 항목을 "수정"이 아닌 "미해결"로 분류.
4. **체크리스트 동기화**: 보고 후 `.claude/workspace/checklist.md` 의 해당 항목 [x] 체크 + 다음 할 일 추가.
5. **맥락노트 동기화**: 비자명한 결정사항이 있으면 `.claude/workspace/context-note.md` 에 한두 줄 추가.

---

## 평가 에이전트(code-auditor / plan-auditor)는 추가 섹션 포함

```markdown
## 검증 결과 (Verdict)
- PASS / FAIL / PASS_WITH_NOTES
- 발견된 이슈 수: critical / major / minor

## 이슈 상세
- [심각도] 위치 (파일:라인) — 설명 — 권장 수정
```

평가 에이전트는 자기가 검토한 작성자의 보고서를 그대로 신뢰하지 않는다. 코드를 직접 열어 확인한다.
